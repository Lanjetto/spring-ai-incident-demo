# Incident Buckets

Система приёма сообщений пользователей и ручной кластеризации их в инциденты
оператором, с последующей группировкой инцидентов в бакеты по уровню критичности.

Обработка полностью ручная: сообщения сохраняются в `raw_messages`, оператор
отмечает нужные, задаёт название и уровень критичности — сообщения переезжают
в `user_message`, а инцидент попадает в бакет.

## Language

**RawMessage (Сырое сообщение)**:
Сообщение пользователя, ещё не отнесённое к инциденту: `{userId, text, timestamp}`.
Живёт в таблице `raw_messages`, пока оператор не выберет его в инцидент.
_Avoid_: ticket, feedback, report

**UserMessage (Сообщение)**:
Сырой отчёт пользователя, отнесённый к инциденту: `{userId, text, receivedAt}`.
Не имеет своего уровня критичности.
_Avoid_: ticket, feedback, report

**Incident (Инцидент)**:
Кластер смыслово похожих сообщений — одна конкретная проблема ("сервер отдаёт 500").
Владеет уровнем критичности и списком сообщений. Создаётся оператором вручную.
_Avoid_: issue, problem, bucket item

**Bucket (Бакет)**:
Срез инцидентов по уровню критичности. Бакет — это не отдельная сущность,
а группировка `Incident` по `SeverityLevel`. Всегда существует ровно четыре бакета (A1–A4).
_Avoid_: queue, category, group

**SeverityLevel (Уровень критичности)**:
Шкала критичности от A1 до A4: A1 = FATAL (ресурс недоступен), A4 = сервисы работают,
но у пользователя проблемы. A1 — самый критичный, A4 — самый спокойный.
Уровень задаёт оператор при создании инцидента, эскалации нет.
_Avoid_: priority, severity number
