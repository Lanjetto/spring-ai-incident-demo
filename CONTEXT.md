# Incident Buckets

Система приёма сообщений пользователей, кластеризации их в инциденты по смысловой близости,
группировки инцидентов в бакеты по уровню критичности и генерации контекстных подсказок
по решению через RAG по историческим инцидентам.

Обработка сообщений асинхронная: HTTP-приём публикует сообщение в Kafka,
консьюмер классифицирует, относит к инциденту и сохраняет.

## Language

**UserMessage (Сообщение)**:
Сырой отчёт пользователя: `{userId, text, receivedAt}`. Не имеет своего уровня критичности.
_Avoid_: ticket, feedback, report

**Incident (Инцидент)**:
Кластер смыслово похожих сообщений — одна конкретная проблема ("сервер отдаёт 500").
Владеет уровнем критичности и списком сообщений.
_Avoid_: issue, problem, bucket item

**Bucket (Бакет)**:
Срез инцидентов по уровню критичности. Бакет — это не отдельная сущность,
а группировка `Incident` по `SeverityLevel`. Всегда существует ровно четыре бакета (A1–A4).
_Avoid_: queue, category, group

**SeverityLevel (Уровень критичности)**:
Шкала критичности от A1 до A4: A1 = FATAL (ресурс недоступен), A4 = сервисы работают,
но у пользователя проблемы. A1 — самый критичный, A4 — самый спокойный.
_Avoid_: priority, severity number

**Escalation (Эскалация)**:
Повышение критичности инцидента к A1 по мере роста числа сообщений внутри инцидента.
Меньший номер = критичнее; A1 = FATAL, A4 = спокойный. Начальный уровень ставит LLM
по первому сообщению; эскалация только повышает критичность (к A1), не понижает.
Пороги конфигурируемы.
_Avoid_: promotion, level-up

**Classification (Классификация)**:
Определение уровня критичности сообщения LLM по тексту. Нераспознанный ответ
модели трактуется как A4 (самый спокойный уровень).
_Avoid_: grading, scoring

**Assignment (Отнесение)**:
Решение LLM, к какому открытому инциденту целевого бакета относится сообщение,
либо создание нового инцидента. Выполняется на основе списка кандидатов-инцидентов
того же уровня критичности.
_Avoid_: matching, routing
